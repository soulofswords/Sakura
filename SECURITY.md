# Security reports

Report reproducible vulnerabilities through this repository's **Security → Advisories → Report a vulnerability** flow when available. Include the affected version, relevant component, expected boundary, reproduction steps and a minimal sanitised example.

Do not include passwords, API keys, Google/Jio tokens, MCP connection files, recordings, private documents or conversation databases. Avoid public issues for unpatched vulnerabilities; general UI bugs without private information can go in Issues.

Test only accounts, workspaces and devices you own or are authorised to test. Disconnect affected integrations and rotate any exposed credentials through the provider. Deleting a file from Git does not remove it from history.

Sakura uses local services, optional phone networking, MCP tools and configurable desktop access. Keep access restricted until you understand a workflow's actions. Automated scans cannot guarantee that every vulnerability is absent. No response-time or security-support guarantee is offered.
