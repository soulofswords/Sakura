# Sakura update — 15 October 2026

## Cloud API settings on PC

- Find available models queries the selected provider only. Gemini listings are filtered for text generation; other catalogs provide candidate chat models. Discovery does not save a newly entered key or change the active provider. Custom HTTPS API endpoints can list models before a model ID is known.
- Selecting a model fills the matching model field. Test API saves the selection and makes a small generation request, with no chat-history or speech changes. Gemini's earlier metadata-only test has been replaced with a generation check. A test can consume provider API credit.
- Errors distinguish billing/quota, temporary rate limits, authentication, permissions and unavailable models. Bounded provider details redact API keys. No keys are trial-sent to other providers. Model discovery does not prove image support, voice quota or general account access.

## Sakura Mobile 0.3.4

- Startup offers Connect to PC and Local. Local renders a model stored on the phone and uses its saved Gemini/OpenAI API key for online replies; a connected PC is unnecessary after model transfer. Local does not currently include an offline language-model inference engine.
- First setup asks for provider/key and Female/Male voice, then connects to the PC with a Passed/Failed result. A successful request automatically opens the PC transfer picker. Existing phone models instead show Use model / Add model; adding a model automatically tries the remembered PC. Chat remains disabled until a model loads.
- PMX and Live2D transfer the entire explicitly selected folder, including nested assets. VRM transfers one file. A folder containing multiple model entries has a selector. Downloads require pairing, verify SHA-256 and reject unsafe ZIP paths. Existing phone models/settings persist when installing the update over the same signed app.
- Send shows preparing and waiting states. The PC shows Sent only after phone storage is confirmed. Errors remain visible. Live2D supports two-finger pinch zoom and one-finger dragging, and dynamic buttons receive press feedback.
- Local chat retains bounded history; Android dictation fills a draft for review. Phone actions support exact app-name launching, time/date, timers/alarms through Android's clock UI, current weather and headlines.
- Explicit ordinary telephone call requests use exact contact-name/number lookup, runtime permissions and a confirmation displaying the number. Assistant speech/replies are muted while the call is active. These native calling and end-of-call behaviors still require physical-device testing; third-party calling apps are not controlled.
- Model discovery and small API generation checks are available on the phone too. Provider-side credit or permission failures cannot be removed by the app.
- Sakura VTuber Mobile retains its existing package/name and PC-controller role; Local assistant and calling permissions are excluded from its UI/build.

## Companion, animation and rendering

- User address can be Sir, Ma'am or no title; startup greeting follows local time. Six procedural 3D dance styles have distinct poses, explicit style changes and honest handling of unsupported named dances. Shared spoken-text cleanup removes stage directions/asterisk narration in Companion and AI VTuber replies. Short original vocalises are experimental and are not full-song reproduction.
- Environment color-wheel updates reach the renderer and background. Startup frame handling defers local GPU warmup, caps framebuffer allocation and releases unused 3D surfaces during Live2D display. Rig diagnostics stay idle until a model is loaded. These changes reduce known flicker/memory triggers; driver-specific intermittent issues still need tester feedback.
- PC and phone buttons have press/click feedback, keyboard focus indication and reduced-motion support. Long operations use busy labels/spinners where available.
- Windows installers use solid compression while retaining runtime features. Installation/update/payload checks verify binaries and user-setting preservation. No character models, imported voice weights, keys, conversations or personal artwork are bundled.

## Verification and limits

Automated coverage includes Python cloud-routing/error/pairing/package tests, Java provider-error classification, JavaScript model/gesture/control regressions, browser rendering of PMX/VRM/Live2D, APK compilation/signing/integrity and Windows installer installation/update checks. Browser native bridges and provider responses use mocks; no user's live key or physical Android calling session was used. Native Android permissions, camera/LAN behavior and real cloud quotas require device/account testing.

Source remains in the private Sakura repository. Public downloads contain compiled/obfuscated builds, not the source tree. Compilation/obfuscation does not prevent all reverse engineering. This update does not include newly built, signed or notarized macOS DMGs; those require a Mac build host.
