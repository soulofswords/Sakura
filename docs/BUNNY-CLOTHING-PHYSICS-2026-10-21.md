Automatic diagnostics reported no corruption because the motion was within its previous limits. This reproduces excessive garment motion, but does not identify visually which top the user meant among the two Bunny models.

Added a firmer, more damped cloth category (18 degree limit) for explicitly named clothing; recognized Chinese hem names as skirt. Actual Tushan clothing maximum after the change was about 15.8 degrees. Default PMX mode already uses springs. No original model assets or saved user bone choices changed.

Validation: production headless load and 720-step idle simulation for both Bunny PMX models, clothing cap checks; actual RightClothArmR2 manual freeze held at rest with zero particle drift and persisted on reload. ## Live-app follow-up

The first damping change was insufficient. Live inspection identified 32 chest spring nodes versus only two chest bones declared dynamic by the Tushan rig. The name-based chest augmentation was incorrectly adding adjustment/deformation helpers even when authored dynamics existed. Restricting augmentation to rigs without declared dynamics preserves the imported physics intent. Actual Tushan production-loader simulation now has 217 physics nodes: 130 hair, 82 cloth, 3 other, 2 chest. The other Bunny model retains all six authored chest physics bones.

A restarted local app initially still showed the old 247/32 counts: its embedded browser cached unchanged module URLs.
